# Notifications API

Base path: `/api/notifications`

All endpoints require a valid JWT (`Authorization: Bearer <token>`).

Notifications are **personal** — each user only ever sees and manages their own. There is no admin override; ownership is enforced at the database level.

---

## Endpoints

| Method | Endpoint | Description |
| :--- | :--- | :--- |
| GET | [`/`](#1-get-) | Paginated notification feed |
| GET | [`/unread-count`](#2-get-unread-count) | Bell-badge unread count |
| PATCH | [`/read-all`](#3-patch-read-all) | Mark all notifications as read |
| PATCH | [`/:id/read`](#4-patch-idread) | Mark a single notification as read |
| DELETE | [`/:id`](#5-delete-id) | Delete a notification |

## Notification Object

```json
{
  "id": "n1a2b3c4-...",
  "userId": "a1b2c3d4-...",
  "notificationType": "CASE_ASSIGNED",
  "entityType": "CASE",
  "msg": "You have been assigned to \"State vs. Sharma 2026\" with VIEW access.",
  "metadata": {
    "case_id": "c1d2e3f4-...",
    "case_title": "State vs. Sharma 2026",
    "access_level": "VIEW",
    "action_url": "/cases/c1d2e3f4-..."
  },
  "isRead": false,
  "readAt": null,
  "createdAt": "2026-05-13T11:00:00.000Z"
}
```

### `notificationType` values

All 11 system notification types and their triggers:

| Type | Entity | Trigger |
| :--- | :--- | :--- |
| `CASE_ASSIGNED` | `CASE` | Admin assigns you to a case |
| `CASE_UNASSIGNED` | `CASE` | Admin removes you from a case |
| `CASE_UPDATED` | `CASE` | Case details changed (title, status, court, etc.) |
| `HEARING_SCHEDULED` | `CASE` | Hearing date added or updated on a case |
| `DOCUMENT_PROCESSED` | `CASE` | Document finished RAG ingestion |
| `DOCUMENT_ERROR` | `CASE` | Document RAG ingestion failed |
| `CHAT_RESPONSE_READY` | `CHAT` | AI finished generating a response (async) |
| `CHAT_ERROR` | `CHAT` | AI response generation failed |
| `CHAT_DOCUMENT_PROCESSED` | `CHAT` | Document processed in a chat context |
| `CHAT_DOCUMENT_ERROR` | `CHAT` | Document error in a chat context |
| `EVENT_REMINDER` | `EVENT` | Upcoming personal calendar event (auto-generated by BullMQ) |

### `entityType` values

| Value | Routes to |
| :--- | :--- |
| `CASE` | `/cases/:case_id` |
| `CHAT` | `/cases/:case_id/chat/:thread_id` |
| `EVENT` | `/events/:event_id` |

### `metadata` shapes per `notificationType`

| Type | Metadata fields |
| :--- | :--- |
| `CASE_ASSIGNED` | `case_id`, `case_title`, `access_level` (`VIEW\|EDIT\|ADMIN`), `action_url` |
| `CASE_UNASSIGNED` | `case_id`, `case_title` — **no `action_url`** (access revoked) |
| `CASE_UPDATED` | `case_id`, `case_title`, `updated_fields` (string[]), `action_url` |
| `HEARING_SCHEDULED` | `case_id`, `case_title`, `hearing_date` (ISO 8601), `court_name`, `action_url` |
| `DOCUMENT_PROCESSED` | `case_id`, `case_title`, `document_id`, `document_name`, `action_url` |
| `DOCUMENT_ERROR` | `case_id`, `case_title`, `document_id`, `document_name`, `error_message`, `action_url` |
| `CHAT_RESPONSE_READY` | `case_id`, `case_title`, `thread_id`, `thread_title`, `action_url` |
| `CHAT_ERROR` | `case_id`, `case_title`, `thread_id`, `thread_title`, `error_message`, `action_url` |
| `CHAT_DOCUMENT_PROCESSED` | `case_id`, `case_title`, `thread_id`, `thread_title`, `document_id`, `document_name`, `action_url` |
| `CHAT_DOCUMENT_ERROR` | `case_id`, `case_title`, `thread_id`, `thread_title`, `document_id`, `document_name`, `error_message`, `action_url` |
| `EVENT_REMINDER` | `event_id`, `event_name`, `event_type`, `start_time` (ISO 8601), `action_url` |

## 1. `GET /`

Returns the authenticated user's notification feed, ordered newest first.
Optionally filtered by `entityType` to support tabbed UI views.

### Query Parameters

| Parameter | Type | Default | Max | Description |
| :--- | :--- | :--- | :--- | :--- |
| `entityType` | string | — | — | Filter by tab: `CASE`, `CHAT`, or `EVENT` |
| `limit` | number | `20` | `100` | Records per page |
| `offset` | number | `0` | — | Records to skip |

**Examples:**
```
GET /api/notifications                        — full feed
GET /api/notifications?entityType=CASE        — case tab
GET /api/notifications?entityType=CHAT        — chat tab
GET /api/notifications?limit=10&offset=20     — paginate
```

### Success Response — `200 OK`

```json
{
  "data": [
    {
      "id": "n1a2b3c4-...",
      "userId": "a1b2c3d4-...",
      "notificationType": "DOCUMENT_PROCESSED",
      "entityType": "CASE",
      "msg": "\"Affidavit_Sharma.pdf\" has been processed and is ready.",
      "metadata": {
        "case_id": "c1d2e3f4-...",
        "case_title": "State vs. Sharma 2026",
        "document_id": "d1e2f3a4-...",
        "document_name": "Affidavit_Sharma.pdf",
        "action_url": "/cases/c1d2e3f4-..."
      },
      "isRead": false,
      "readAt": null,
      "createdAt": "2026-05-13T11:05:00.000Z"
    }
  ],
  "total": 14,
  "limit": 20,
  "offset": 0
}
```

### Error Responses

| Status | Error | Cause |
| :--- | :--- | :--- |
| `400` | `entityType must be one of: CASE, CHAT, EVENT.` | Invalid filter value |
| `401` | `Unauthorized. No token provided.` | Missing JWT |
| `401` | `Invalid or expired token.` | Bad or expired JWT |
| `500` | `Internal server error.` | Unexpected server failure |

## 2. `GET /unread-count`

Returns the count of unread notifications. Designed for the bell-icon badge — cheap query backed by a composite index.

### Success Response — `200 OK`

| Status | Error | Cause |
| :--- | :--- | :--- |
| `401` | `Unauthorized. No token provided.` | Missing JWT |
| `401` | `Invalid or expired token.` | Bad or expired JWT |
| `500` | `Internal server error.` | Unexpected server failure |

## 3. `PATCH /read-all`

Marks **all** unread notifications for the authenticated user as read in a single query.

### Success Response — `200 OK`

```json
{
  "message": "7 notification(s) marked as read."
}
```

> Returns `"0 notification(s) marked as read."` if there were no unread notifications — not an error.

### Error Responses

| Status | Error | Cause |
| :--- | :--- | :--- |
| `401` | `Unauthorized. No token provided.` | Missing JWT |
| `401` | `Invalid or expired token.` | Bad or expired JWT |
| `500` | `Internal server error.` | Unexpected server failure |

---

## 4. `PATCH /:id/read`

Marks a single notification as read. **Idempotent** — calling this on an already-read notification returns `200` without error.

### URL Parameters

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID string | Notification ID |

### Success Response — `200 OK` *(newly marked)*

```json
{
  "notification": {
    "id": "n1a2b3c4-...",
    "userId": "a1b2c3d4-...",
    "notificationType": "CASE_ASSIGNED",
    "entityType": "CASE",
    "msg": "You have been assigned to \"State vs. Sharma 2026\" with VIEW access.",
    "metadata": { "case_id": "...", "case_title": "...", "access_level": "VIEW", "action_url": "..." },
    "isRead": true,
    "readAt": "2026-05-13T12:00:00.000Z",
    "createdAt": "2026-05-13T11:00:00.000Z"
  }
}
```

### Success Response — `200 OK` *(already read)*

```json
{
  "message": "Notification already marked as read."
}
```

### Error Responses

| Status | Error | Cause |
| :--- | :--- | :--- |
| `401` | `Unauthorized. No token provided.` | Missing JWT |
| `401` | `Invalid or expired token.` | Bad or expired JWT |
| `404` | `Notification not found.` | ID does not exist or belongs to another user |
| `500` | `Internal server error.` | Unexpected server failure |

---

## 5. `DELETE /:id`

Permanently deletes a notification. Only the owner can delete.

> Prefer keeping notifications and letting the archival cron clean them up. Use DELETE only for explicit user-triggered dismissal.

### URL Parameters

| Parameter | Type | Description |
| :--- | :--- | :--- |
| `id` | UUID string | Notification ID |

### Success Response — `200 OK`

```json
{
  "message": "Notification deleted."
}
```

### Error Responses

| Status | Error | Cause |
| :--- | :--- | :--- |
| `401` | `Unauthorized. No token provided.` | Missing JWT |
| `401` | `Invalid or expired token.` | Bad or expired JWT |
| `404` | `Notification not found.` | ID does not exist or belongs to another user |
| `500` | `Internal server error.` | Unexpected server failure |
